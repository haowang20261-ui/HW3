## Overview

This assignment uses the FEMNIST handwritten-character dataset (100 clients; 62 character classes) to implement and evaluate:

- **Part 1.1 — Serial FedAvg:** deterministic client sampling, local stochastic gradient descent (SGD), sample-size-weighted aggregation, and comparisons of client participation and local epochs.
- **Part 1.2 — Parallel FedAvg with Ray:** CPU-based client actors, numerical consistency checks against serial FedAvg, and runtime/robustness experiments.
- **Part 2 — Laplace-Perturbed FedAvg:** independent Laplace noise added to local training pixels, with comparisons across noise scales and client-level robustness analysis.

The neural network is a two-layer MLP: **784 inputs → 128 ReLU units → 62 outputs** (108,478 trainable parameters).

## Algorithm Pseudocode

**Part 1 — FedAvg (serial or Ray):**

```text
Initialize global model weights w and fixed client data splits.
For each communication round t:
    Select participating clients deterministically.
    For each selected client k (serially or using Ray actors):
        Start from a copy of w.
        Run E local epochs of mini-batch SGD on client k's training data.
        Return local weights w_k and local training sample count n_k.
    Update w = sum_k (n_k / sum_j n_j) * w_k.
    Evaluate on the shared validation partition.
    Save training history and checkpoints at configured intervals.
Select the best checkpoint using validation metrics, not test results.
```

**Part 2 — Laplace-Perturbed FedAvg:**

```text
For each client k, sample fixed independent pixel noise:
    epsilon_k[pixel] ~ Laplace(0, b), using the configured seed.
    noisy_train_k = clean_train_k + epsilon_k (without clipping).
For each communication round:
    Select clients using the same FedAvg sampling rule.
    Train each selected client locally on noisy_train_k.
    Aggregate the returned models with sample-count weights.
    Evaluate on clean validation images and save checkpoints/history.
Compare final models for b = 0, 0.02, 0.05, 0.10, 0.20, 0.40.
```

**Privacy note:** Adding Laplace noise to pixels does not, by itself, establish a formal differential privacy guarantee. The report discusses the privacy–utility trade-off and the additional assumptions/privacy accounting needed for a formal claim.
